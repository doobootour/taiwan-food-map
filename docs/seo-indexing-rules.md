# 맛집 상세 페이지 색인 기준

적용 대상은 개별 맛집 상세 URL뿐이다.

`/<region>-<category>-<가게이름>-<id>` 또는 이름을 라틴 문자로 바꾸지 못한 `/<region>-<category>-<id>`

홈, 지도, 지역, 카테고리, 지역×메뉴 조합, 블로그, 게시판, 소개, 개인정보 페이지는 이 규칙으로 `noindex` 하지 않는다. 상세 페이지가 색인 대상이 아니어도 파일은 그대로 두고, 지도·지역·카테고리·조합 페이지의 링크도 지우지 않는다.

## 색인하는 경우

`eats.review`(한줄평) 또는 `eats.address`(주소)를 앞뒤 공백을 뺀 뒤 **8자 이상**이면 색인한다. sitemap에도 넣는다.

둘 다 8자 미만이면(비어 있는 경우 포함) 상세 HTML에 다음 태그를 넣고 sitemap에서는 뺀다.

```html
<meta name="robots" content="noindex,follow" />
```

8자는 2026-09-28에 `eats`를 읽어 정한 값이다. 한줄평이 있는 174곳의 가장 짧은 글이 8자(`우육면으로 추천`)였고, 1~7자짜리 한줄평은 한 건도 없었다. 그래서 8자 미만은 빈 값과 같고, 이미 등록된 한줄평은 하나도 잘리지 않는다. 주소만 있는 5곳은 모두 영문 도로명 주소로 8자를 넘어서 색인 대상이다.

세지 않는 것:

- 가게 이름. 상세 페이지마다 같은 템플릿 문장 안에만 들어간다.
- 닉네임. 등록한 사람의 이름이다.
- 지역명, 카테고리명, 좌표, 구글맵 링크, 근처 맛집 목록. 공통 템플릿이다.

## 자동으로 되돌리기

`scripts/lib/indexable.js`의 `isIndexableSpot()`이 기준의 단일 구현이다. `scripts/generate-spot-pages.js`와 `scripts/generate-sitemap.js`가 둘 다 이 함수를 쓴다. 매일 재생성이나 수동 실행 때 Supabase에서 `review`와 `address`를 다시 읽는다.

한줄평이나 주소가 나중에 8자 이상이 되면 다음 실행에서 `noindex` 메타를 빼고 sitemap에 그 URL을 다시 넣는다. 반대로 한줄평과 주소가 기준 아래로 내려가면 다시 `noindex` 하고 sitemap에서 뺀다. 맛집 데이터 자체는 이 규칙으로 수정하지 않는다.

2026-09-28에 생성기를 실행했을 때 상세 페이지 802곳 중 179곳이 색인 대상(한줄평 174, 주소만 있는 곳 5)이고 623곳이 `noindex,follow`였다. sitemap의 상세 URL도 179개였다.
